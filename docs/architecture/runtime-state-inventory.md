## Policy defaults and override boundary

- Every production state uses a versioned policy key. Policy publication must record owner, class, default and minimum retention, sensitivity, backup behavior, erase behavior, reference checks and legal-hold eligibility.
- A workspace may extend a policy only where the policy allows it. A workspace may never reduce `legal_audit_retention`, security/audit evidence, or any declared minimum retention.
- Product retention is driven by owner lifecycle state. Technical TTL is driven by expiry plus replay/lease safety. A user erase request is an independently verified workflow and never silently overrides legal/audit retention.
- Backup erase is delayed: a restored backup must replay the deletion registry before the restored Runtime is exposed. Online purge completion does not claim immediate removal from compliance-locked backups.
- Region follows workspace placement unless a provider contract declares an additional region. Cross-region archive/export requires an explicit provider and workspace policy decision.

## Unbounded-growth enforcement closure

Every Runtime collection in this inventory has an enforcement mode. Record Timer terminal rows use the existing Record product-retention policy; the Record persistence lifecycle executor archives/purges `record_timer_event` children before their terminal `record_timer` parent and never uses `scheduler.execution.v1`. The fenced lifecycle worker covers Runtime-owned Audit; Workflow definition/process/execution/receipt state with child-before-parent ordering; Automation; Integration event/invocation/outbox/transaction-boundary evidence/nonces/expired leases; Operations receipts and expired Break-glass grants; action/record idempotency receipts; soft-deleted dynamic business records; Metadata versions; Notification versions/publication requests/delivery reservations; Report snapshots/business governance records; and expired rate-limit buckets. Agent, Data Exchange and Scheduler own their Module/SaaS state and retention. The upload registry separately reconciles final file references, observes orphan grace, deletes mature orphans, and retains hash/size/status evidence; the same worker removes interrupted `.upload-*` staging files and expired subject exports.

Policies for source-driven localization, current Runtime configuration, installation-lifetime migration evidence, and reconstructable caches are explicitly classified as subject-governed, bounded-current, permanent evidence, or cache eviction rather than generic purge. `TestEveryDefaultRetentionPolicyHasAnExplicitEnforcementMode` fails when a new default policy lacks one of these reviewed modes.

Any newly introduced mutable collection must be classified here before release. Durable business or audit state must not depend on process memory; local caches must remain reconstructable and safe under multi-instance divergence.
